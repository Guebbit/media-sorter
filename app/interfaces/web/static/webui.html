Progress

The three steps below run in order, and each one is safe to repeat. Run everything, top right, does all three in one press — the same work, without waiting to click between them.

1 Find the photos …
Records every image file in your photo folders — name, size, date, checksum. It does not look at the pictures, so afterwards every photo is unprocessed. Fast, and safe to repeat: re-running it only picks up what is new or changed.
2 Look at the photos …
The slow step, and the only one that opens the pictures. The detector finds objects in every unprocessed photo, then your rules turn what it found into a category and an action. Nothing is moved or written outside the database yet.
It resumes where it stopped, so if it ended early — page closed, server restarted — press it again.
3 Sort them into folders …
Carries out what step 2 decided: creates the links in the output folder, and runs the actions that touch your originals — move and delete — whenever a rule asks for them. Photos whose action is ignore produce nothing — that is what the action means, and it is why this step can finish with nothing to do. Running it twice creates nothing the second time.
↻ After editing rules optional
Re-decides every photo from the detections already stored — instant, no GPU, no second look at the pictures. Use it after changing rules, then press Sort now again.
What the words mean

Every step stores its result in the database, which is what makes each one resumable and repeatable: nothing is ever processed twice, and a step you run again only picks up what is left.

A photo is only sorted if the detector actually found something your rules ask for, above the confidence threshold. Everything else falls through to your last rule.

unprocessed Indexed, but the detector has not looked at it yet — press Examine photos in step 2.
none The detector looked and found nothing your rules ask for, so the final catch-all rule matched. With the starter rules its action is ignore.
ignore An action, not a failure: leave this photo alone. It stays indexed and searchable, produces no link, and skips the semantic pass.
copy Put a duplicate of the photo in its folder. The original stays put.
move Put the photo itself in its folder — nothing left behind.
delete The original goes to the trash folder instead of a category folder.
_Review Where the built-in in doubt rule sends a photo nobody could settle, instead of a category folder. With the second opinion on, a photo only lands here once the vision model has looked and answered unsure too.
present /
absent /
unsure		 What the second opinion said about a class the detector half-saw. present promotes it to a real match, absent drops it, unsure sends the photo to a person.
Detections empty No objects found in anything scanned so far. If that is unexpected, the confidence threshold may be too high, or these photos simply do not contain what the rules look for.
Preview what would happen

Nothing is written by either button. Use this before enabling any rule that moves or removes your originals.
Preview what would happen plans the real work: every link that would be created, every file that would be deleted, from the decisions already stored. What if I applied these rules? answers a different question — it re-runs the current rules over the detections in the database and reports which category each photo would land in, so you can judge a rule edit before committing to it.
Both need step 2 above to have examined some photos first: with nothing detected there is nothing to plan, and both will honestly come back empty.
